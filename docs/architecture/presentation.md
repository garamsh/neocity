# Presentation

How the GDExtension presents both games and the menus through input, camera motion, and a drawn frame, and hosts the experiment scenes.

## Current decisions

- The `neocity` GDExtension library is built from `src/register_types.cpp`, `src/scene.cpp`, and the session, camera, input, rendering, and HUD folders. It depends on the rules libraries' public surfaces and godot-cpp 10.0.0-stable, and compiles each experiment's `view/` node. The root `build_profile.json` limits the generated bindings to the Godot classes it uses.
- `src/register_types.cpp` is the extension entry point (`neocity_init`) and registers `AscentScene` and each experiment's node class.
- `src/scene.cpp` (`AscentScene`) is the composition site and frame adapter: it constructs the ascent engine, camera, session, drawing, and one `SurvivalRules` per survival run, forwards frame input and drawing to session, and mounts the experiment scene session selects as its child. It exposes `survival_status()` and `pin_survival_seed()` for the Godot checks; an unpinned run takes its seed from Godot's random generator. It also provides session's `CinematicStage`: it loads a cinematic scene as its child, closes it on the `finished` signal, and reports a scene that cannot play instead of aborting, unlike the experiment mount, whose scenes are always registered.
- `src/session/` owns selection and run orchestration as described in [session](session.md).
- `src/input/` translates Godot input actions into menu actions, the ascent command, and the survival input of each human actor. `project.godot` binds the `survival_1_*` and `survival_2_*` actions.
- `src/camera/` follows the leading actor vertically.
- `src/rendering/` loads the level textures and Godot's fallback font, and paints the city depth, course, obstacles, and actors. It owns the shared drawing primitives and color palette. `src/rendering/survival.cpp` paints the survival game in `_draw` primitives: the monster's mouth with its acid line, the city grid with a mark for every destroyed, depleted, or unavailable object, and the workshop. A gold frame promises stock a player can walk to: stock no human can reach has a dashed white frame and says so in its label, so the difference is not colour alone. Every word on the map sits on an opaque plate, so the acid behind it cannot change its contrast, and each source's count is painted over the actors. It reuses the ascent atlas's chef and appraiser sprites.
- `src/hud/` paints the interface and the pause/completion overlays over the world, using the rendering primitives. It also draws the main menu, the developer page, the choice of players, and the survival HUD. The survival HUD reads one `SurvivalFrame` of snapshots and shows the day with the day escape checks begin, read from `TEMPORARY_ESCAPE` with no chance shown, acid against the rules' full value, time, each actor's controller, health, stamina, location and tools, the pack, the base tool states, the recipes with their taste, a marker on the dish the chef's key would cook and that dish's forecast from `dish_score`, stored dishes with their quality and score, the ingredients eaten so far, the last day's result over the kitchen, which reads snapshots and so holds no clock and waits for no key, an event log clear of the monster's bowl, and a NEXT line naming what to do now, with the time a collection spends there and in the key line. Text is 13px or larger. `changing_text` lists each line that changes with play, the cook panel's status in every form a pack could give it, with the width its place allows, so `project/e2e/survival.gd` can measure them. Under a cinematic it paints the dark stage, or the placeholder card when no scene can play, as the [cinematic contract](session.md#cinematic-contract) describes.
- The NEXT line asks `SurvivalRun`'s offers what the human's key would do with the current view, so the offer it names is the command the key runs.
- A stored food the monster rejected cannot be fed, so the feed key does nothing with it. At base the NEXT line runs in this order: appraise, replace a damaged tool, cook when no stored dish can be fed, set out, feed, end the day unfed. Set out is named only while `survival::worth_entering` says the first human has an errand from the entrance, because feeding ends the day and a stored dish keeps. While an AI chef has a dish it would cook and no stored dish can be fed, it says so, because that chef cooks on its next step. With nothing to do it names Feed, or ending the day unfed when no stored dish can be fed, whatever time is left, since a higher acid is what brings the next bag. In the city it names the object AI in the human's place would walk to and the direction of the first step, and a collection, with its time cost, only where AI would stop, so a source passed on the way to what the party lacks does not spend the clock; the interact key still takes from it, and still repairs a passage the line leaves out. With two humans in the city it gives each player's line. It says nothing is within reach when no stocked source, or passage that actor can repair to open the way to stock, can be walked to. The two lines judge the same human by the same search, so following them cannot circle; a partner's errand is not counted, so a human leaves an AI partner's repair undone by going home. The two lines share `Companion`'s search, which uses the public cell rule movement uses. The map's marks search the same rule from each human: from where they stand in the city, from the entrance at base.
- An experiment's node presents itself, in 3D for `pan_dodge`, with Godot's primitive meshes, materials, lights, camera, and labels, as [experiments](experiments.md) describes.
- Godot provides window, input, resource, canvas, and 3D primitives. No custom GPU backend is implemented.
