# Session

The main menu, the developer page, run lifetime, and fixed-step delivery to the survival and ascent games.

## Current decisions

- `src/session/` receives the ascent engine, its camera and fresh-run reset, a survival run factory, the experiment catalog, a mount operation, and a `CinematicStage` from `src/scene.cpp`. It decides which screen is open and delegates drawing to rendering and HUD.
- The start screen is the main menu: 1 opens the survival game's choice of players, 2 opens the developer page, and 3 plays the earlier ascent prototype. The choice of players takes 1 for the chef, 2 for the appraiser, and 3 for two local players. The developer page numbers the [registered experiments](experiments.md#registered-experiments). M goes back one level: from a game, the choice of players, or the developer page to the main menu, and from an experiment to the developer page.
- Every transition clears accumulated time, pending input edges, and the open game's run, closes any cinematic, and unmounts any experiment. Controls must be released before the next screen accepts input; an experiment's scene is mounted only then, so a held key cannot become its first action.
- An experiment, once mounted, reads its own input and steps its own rules; session only mounts and unmounts it.
- For the ascent game, frame time is bounded and accumulated into fixed 120 Hz rule ticks. Input edges are retained until a tick consumes them, preserving input sampled between ticks.
- For the survival game, `SurvivalRun` accumulates real frame time, unbounded, into fixed 100ms steps, as the [PM decision on #28](https://github.com/garamsh/neocity/issues/28#issuecomment-6553578708) requires, so time is neither lost nor doubled at any frame rate. Godot cuts `delta` to what `physics/common/max_physics_steps_per_frame` allows, which at the default of 8 and 120 ticks a second loses time below 15 fps, so `project/project.godot` sets 100000, a frame of about 14 minutes. The setting is global, and [experiments](experiments.md) keep their own time delivery under it. The step clock runs in every phase: each step applies both actors' commands and calls `Exploration::advance` once with `Simulation`'s acid, and `Exploration` spends exploration time only while someone explores, so expiry leaves no remainder to carry and workshop steps spend nothing. A new run starts from an empty accumulator.
- A survival step reads a fresh view for each actor after applying the other's action. Edges are retained until a step consumes them. A direction press shorter than a step walks one cell; a key held across a step stops walking when released. A press and release inside a single frame arrives as `PlayerInput`'s `tap`, walks one step at any frame length, and takes that step from a key still held.
- When two humans finish the day in one step, only the first command runs; `SurvivalRun` compares the day before each day-finishing action.
- `SurvivalRun` ignores the last human's leave, because a party of AI alone has no key to take an actor back. When two humans leave in one step, the chef's leave applies and the appraiser's human stays.
- `SurvivalRun` calls `Escape::check` after each command, so a finished day rolls before the partner's command can set out. An escape or a loss ends the step and the run takes no further step. The rules decide a loss first, as [survival](survival.md#loss) records.
- `SurvivalRun` holds a human chef's chosen dish, since `Companion`'s offer is only a suggestion. A press of up or down in the workshop phase, read from the key itself and not from movement's held direction, moves the choice through the dishes that can be cooked now, wrapping at the ends; a held key is one press, and other held keys do not change that. With a choice that can be cooked, the chef's cooking is that `Cook`, for the key and for the screen's offer alike, so the dish named is the dish cooked. With no choice, or one whose ingredients ran out, the chef's key cooks `Companion`'s offer, and the panel marks that instead. A choice lasts for the day, so yesterday's dish does not override an uneaten one. An AI chef is not affected. Using the movement keys adds no input action; these bindings are temporary.
- `SurvivalRun` calls `Exploration::damage` when an actor steps into a hazard cell from outside it, and records actions, hazard hits, falls, expiry, destruction, and exposure as events for the screen.
- `project/e2e/survival.gd` plays the game with real key events: two full days as the chef with AI, a third and fourth day ended unfed, a run choosing a dish and following the NEXT order, a run following only the NEXT line until the stock is gone, a run as the appraiser, the second key set, and a run to an escape with a dish ready. `project/tests/survival_timing.gd` injects action values to verify the fixed step at 480 and 5 frames per second, retained edges, expiry, the one-day guard, and the last-human guard. `--fixed-fps` bypasses Godot's cut of `delta`, so its `-- real-clock` run delays real frames with no such flag, compares exploration time with the wall clock, and confirms that `pan_dodge` keeps its rule-tick limit. `project/e2e/escape.gd` plays from the main menu to the ending with real key events on what the NEXT line says, once at 60 and once at 5 frames per second so that one frame spans two steps, and drives the cinematic contract below with no asset, a working stand-in scene, and broken ones; it installs each stand-in with `Resource.take_over_path`, so nothing is written to the art folders, and its `-- real-clock` run holds the intro card's length on delayed real frames. `project/e2e/loss.gd` does the same to a loss by pressing only the end-day key. These harnesses walk the way the NEXT line's words say, as a player does. `project/e2e/experiments.gd` drives both menus and an experiment with real Godot key events. `project/tests/session_timing.gd` injects action values at a faster frame cadence to verify partial-tick time disposal across a transition, accumulation, and retained input edges.

### Cinematic contract

The agreement between the host and the opening and ending art of [#29](https://github.com/garamsh/neocity/issues/29). The seam is `CinematicStage`, which `src/scene.cpp` provides to session.

- **Location:** `project/levels/monster_mouth_escape/cinematics/intro/intro.tscn`, `project/levels/monster_mouth_escape/cinematics/ending/ending.tscn`, and `project/levels/monster_mouth_escape/cinematics/loss/loss.tscn`, each scene with its assets in its own folder. None exists yet.
- **Scene:** the root is a `CanvasItem`, such as a `Node2D` or a `Control`, because the host paints an opaque dark stage that would hide a 3D root. It declares a `finished` signal with no arguments and emits it once when playback is done; with arguments the host cannot receive it and stays on the scene. The host adds the root as a child of the game scene.
- **Request:** session plays the intro when a run starts, the ending when the run escapes, and the loss when it is lost.
- **End:** on `finished` the host closes the scene, by the end of that frame. The signal may fire from `_enter_tree` on, `_ready` included; the host connects it only after instantiating, so one fired in `_init` is not heard.
- **Skip:** the interact key of any human closes the scene at once, so a scene cannot rely on reaching its own end.
- **Input block:** while a cinematic is open the run takes no key and no time, and the skip does not reach it. M still leaves for the main menu and ends the run.
- **Return:** the intro hands over to day one at base. The ending and the loss close the run and return to the main menu.
- **Fallback:** a scene that is missing, that does not load as a scene, that does not instantiate, whose root is not a `CanvasItem`, or that has no `finished` signal opens a placeholder card instead, under the same skip, input block, and return. The host never aborts for a cinematic. A skip-free card stands 4 seconds for the intro and 6 for the ending and the loss; the lengths are temporary.

## Rationale

[ADR 0005](adr/0005-isolate-experiment-rules-behind-one-host.md) shares the window and menus while each experiment stays self-contained. Session orchestration leaves the `AscentScene` composition contract thin and avoids a generic plugin framework.
