# Godot runtime

The minimal engine host and the checks that establish it can start.

## Current decisions

- The Godot project is `project/`: `project/project.godot` launches `project/main.tscn` with the C++ `MainScene` as the composition root, opening on the title screen. Physics keeps Godot's default tick rate, and `project/project.godot` raises the physics steps a frame may run so that Godot does not cut the frame time the [survival clock](session.md) spends. `project/bin/neocity.gdextension` loads the optimized CMake-built library, which the build writes beside it into `project/bin/` and `.gitignore` excludes, for both editor and game.
- Standard Godot 4.7.2 hosts window, input, imported textures and sounds, audio players and buses, and canvas primitives. `project/default_bus_layout.tres` adds the Effects and Music buses to the master bus; headless, Godot's dummy audio driver stands in for a device, so the checks run with none. Godot 4.7.2 frees a stopped playback only in the audio thread's next mix, and one the audio server still lists when it shuts down is never freed and is reported as leaked at exit ([`servers/audio/audio_server.cpp`](https://github.com/godotengine/godot/blob/4.7.2-stable/servers/audio/audio_server.cpp#L1653-L1663)); the speaker therefore waits for that mix as the scene leaves the tree. The C++ game rules are owned by [survival](survival.md), and the C++ presentation by [presentation](presentation.md); GDScript remains verification-only.
- C++20 with godot-cpp 10.0.0-stable targeting the Godot 4.7 API. godot-cpp and GoogleTest are pinned by archive digest in the CMake files; CMake, Ninja, clang-format, and clang-tidy are pinned by wheel hash in `Makefile` and installed under ignored `.tools/cpp` by the first entry point that needs them. The production GPU backend and broader platform integration remain open.
- `make build` configures and compiles the C++ targets before Godot import, and lists the extension in `project/.godot/extension_list.cfg` first so a fresh checkout loads it at boot. Without the list, the import finds the extension as new and regenerates its documentation, and Godot 4.7.2 can crash on exit running what that queued ([godotengine/godot#111048](https://github.com/godotengine/godot/issues/111048)). Godot 4.7.2 imports the three fonts on worker threads at once, and each one's first save fills ClassDB's cache of default property values with no lock held ([`core/object/class_db.cpp`](https://github.com/godotengine/godot/blob/4.7.2-stable/core/object/class_db.cpp#L2172-L2207)), so an import into an empty `project/.godot` can crash ([godotengine/godot#111039](https://github.com/godotengine/godot/issues/111039), fixed for 4.8 by [godotengine/godot#123546](https://github.com/godotengine/godot/pull/123546)). `project/project.godot` therefore sets `editor/import/use_multiple_threads` to false, the project setting 4.7.2 reads before importing files of one importer on worker threads ([`editor/file_system/editor_file_system.cpp`](https://github.com/godotengine/godot/blob/4.7.2-stable/editor/file_system/editor_file_system.cpp#L3333)), so every import runs on the main thread, one file at a time. Remove the setting when the pinned Godot moves to a release that carries godotengine/godot#123546, 4.8 or later. `make test` runs the survival library's unit tests through CTest, shipped-scene readiness, live input checks covering the title screen and the survival game, the survival timing checks, and the sound checks of `project/e2e/audio.gd`. `make lint` runs clang-tidy and `make format` checks clang-format; `make ci` runs the full set. Every Godot command runs with `--path project`, so concept images in `docs/`, local tools, C++ source, and the build directory are outside the project Godot imports and need no `.gdignore`. The survival frame capture harness writes to Godot's `user://` directory, outside `project/`.
- macOS setup installs the verified official Godot under ignored `.tools/` and requires the Xcode Command Line Tools for the compiler and Python; no global PATH changes or account authentication are required. CI prepares Python with the pinned setup action and checksum-verified Linux Godot, then runs the same Make entry point with the runner's system compiler. CI keeps core dumps, and a failed job prints each one's signal and thread stacks, because a crash during Godot's shutdown can leave no text in a piped log.

## Rationale

[ADR 0002](adr/0002-isolate-the-ascent-engine-from-presentation.md) keeps game rules independent of the host, [ADR 0003](adr/0003-implement-the-ascent-domain-in-cpp.md) selects C++ with godot-cpp, and [ADR 0004](adr/0004-adopt-the-godot-cpp-template-layout.md) the godot-cpp template's project layout and the level folders under `project/levels/`. [ADR 0006](adr/0006-ship-one-game-behind-a-title-screen.md) moves the host scene to `project/main.tscn` and removes the ascent level and the experiment scenes. GDExtension supplies the smallest native binding for this slice without moving rules into GDScript or claiming a standalone renderer.

## Open questions

- Additional host services when later approved game behavior needs them.
